# 🔐 Solenoid Door Access Control

An Arduino Nano–based electronic door lock system that replaces traditional mechanical keys with PIN-based authentication. Enter the correct password on a 4×4 keypad and a relay-driven solenoid lock retracts to grant access — wrong entries are rejected, logged, and locked out after repeated failures.

Designed end-to-end: schematic → PCB layout → fabrication-ready Gerbers → firmware.

---

## ✨ Features

- 🔢 **4×4 keypad PIN entry** with masked input on a 16×2 LCD
- 🔒 **Fail-safe default-locked state** — solenoid stays locked unless explicitly triggered
- ⏱️ **Auto re-lock** after a configurable unlock window
- 🚫 **Brute-force protection** — lockout timer after repeated failed attempts
- 🔁 **In-field password change** (old PIN → new PIN) with **EEPROM storage** so it survives power loss
- 🔊 **Audible + visual feedback** via buzzer and green/red status LEDs
- 🖥️ Custom two-layer **PCB** designed and routed from scratch (Gerbers + drill files included)

---

## ⚙️ How It Works

1. On power-up, the Arduino initializes all peripherals and keeps the solenoid **locked** by default.
2. The user enters a 4-digit PIN on the keypad; each digit is masked on the LCD.
3. Pressing `#` submits the PIN for verification against the stored value.
4. **Correct PIN** → relay energizes the solenoid, door unlocks, green LED + short beep, auto re-locks after a timeout.
5. **Incorrect PIN** → red LED + buzzer alert, door stays locked; after 3 failed attempts the system enters a 15-second lockout.
6. Pressing `A` at any time opens a guided password-change flow, storing the new PIN in EEPROM.

**Governing physics** (solenoid actuation):

```
F ∝ N · I          (Force generated by current through coil)
B = μNI / L         (Magnetic field in the coil)
V = IR              (Ohm's Law — current through solenoid)
P = V · I           (Power consumption, for supply/relay sizing)
```

## 🧰 Hardware

| Component | Details |
|---|---|
| **Microcontroller** | Arduino Nano (ATmega328P) |
| **Input** | 4×4 matrix keypad (PIN entry) |
| **Display** | 16×2 LCD (parallel interface) |
| **Actuator** | 12V DC solenoid door lock |
| **Driver** | Relay module (+ flyback diode for back-EMF protection) |
| **Feedback** | Buzzer, green LED (access granted), red LED (access denied) |
| **Power** | 5V for logic, 9–12V external supply for the solenoid |

### Pin Map (Arduino Nano)

| Function | Pin(s) |
|---|---|
| LCD (RS, E, D4–D7) | 12, 11, 5, 4, 3, 2 |
| Keypad Rows | A0, A1, A2, A3 |
| Keypad Columns | 6, 7, 8, 9 |
| Relay (solenoid driver) | 10 |
| Buzzer | A4 |
| Green LED | A5 |
| Red LED | 13 |

> Adjust pin assignments in the firmware if your wiring/PCB differs.

## 🔩 PCB Design

A custom two-layer PCB was designed to host the Nano, relay, buzzer, OLED, keypad header, and power input — laid out and routed manually in Altium Designer, then exported to industry-standard Gerber/drill files for fabrication.

**Component placement (silkscreen legend):**

Keypad header, Buzzer, Relay, Nano footprint, OLED display, and 9–12V power input footprint, arranged for clean routing and minimal trace crossover.

**Signal routing (top + bottom copper):**

Signal traces connect the keypad rows/columns, relay control line, OLED I²C/SPI lines, and power rails between the Nano and peripheral footprints, with dedicated power pours for the 9–12V solenoid supply.

**Drill report summary:**

| Tool | Hole Size | Count | Type |
|---|---|---|---|
| T1 | 0.8 mm | 2 | PTH |
| T2 | 0.9 mm | 41 | PTH |
| T3 | 1.0 mm | 4 | PTH |
| T4 | 2.0 mm | 4 | PTH |
| T5 | 3.35 mm | 2 | PTH |
| T6 | 3.74 mm | 1 | PTH |

**54 total plated through-holes**, all routed with a top-to-bottom layer pair.

> Gerber files (`PCB1_Profile`, `PCB1_Legend_Top`, `PCB1_Copper_Signal_Top/Bot`) and the drill report (`PCB1.DRR`) are included in [`/hardware`](./hardware) for anyone who wants to fabricate the board.

## 🚀 Getting Started

### 1. Hardware Assembly
Wire the components per the [pin map](#pin-map-arduino-nano) above, or fabricate the included PCB and populate it with the listed components.

### 2. Flash the Firmware
1. Open `firmware/Solenoid_Door_Access_Control.ino` in the Arduino IDE.
2. Install the required libraries via Library Manager: `Keypad`, `LiquidCrystal` (built-in), `EEPROM` (built-in).
3. Select **Board: Arduino Nano** and the correct COM port.
4. Upload.

### 3. Default Credentials
- Default PIN: `1234`
- Change it any time by pressing `A` on the keypad and following the on-screen prompts.

## 🛡️ Design Considerations

- **Fail-safe locking**: the solenoid defaults to locked on boot and on power loss — the door never fails open.
- **Back-EMF protection**: a flyback diode across the relay coil protects the driver transistor when the solenoid de-energizes.
- **Brute-force resistance**: a 3-strike lockout with a cooldown period discourages rapid PIN guessing.
